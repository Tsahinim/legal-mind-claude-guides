1

מהו Project ולמה הוא שונה משיחה רגילה?

Project הוא מרחב עבודה עצמאי בתוך Claude. יש לו היסטוריית שיחות משלו, בסיס ידע משלו והוראות משלו. כל שיחה שנפתחת בתוך המרחב יכולה להיעזר בקבצים ובהוראות שנשמרו בו.

זמינות ודרך כניסה
Projects זמינים בכל המסלולים. בחשבון Free אפשר ליצור עד חמישה Projects. כדי להגיע אליהם פתחו את סרגל הצד ולחצו על Projects. אפשר גם לפתוח ישירות את עמוד claude.ai/projects.
Chatsשיחות ממוקדות שמתנהלות בתוך אותו מרחב.
Filesחומרי הידע שהשיחות במרחב יכולות להפנות אליהם.
Instructionsכללי העבודה שחלים על כל שיחה בפרויקט.
Memoryיכולת אופציונלית, אם היא זמינה ומופעלת בחשבון. היא עשויה לסייע בשמירת הקשר, אך אינה מחליפה קובץ או הוראה שניתן לאתר ולבדוק.
שמירת מידע שצריך להישאר זמין

היכן נשמר מידע שצריך להיות זמין בשיחות נוספות

שיחה קודמת אינה הופכת אוטומטית למסמך ידע. כאשר מידע חייב להיות זמין לכל שיחה חדשה, שמרו אותו בקובץ מאושר או בהוראות. Memory עשוי לסייע כאשר הוא מופעל, אך אינו תחליף למקור שניתן לאתר ולבדוק.

2

ליצור Project חדש ולהגדיר לו גבול ברור

יצירת Project מתחילה מעמוד Projects. השם והתיאור עוזרים לבני האדם לזהות את המרחב, אך Claude אינו משתמש בהם כהקשר. את המידע והכללים שצריכים להשפיע על התשובות מוסיפים לאחר ההקמה ל־Project Instructions ול־Project Files.

  1. פתחו את הסרגל הצדדי ולחצו על Projects.
  2. בעמוד Projects לחצו על + New Project בפינה העליונה.
  3. הקלידו שם ותיאור שאינם חושפים מידע רגיש שלא לצורך.
  4. בחשבון Team או Enterprise בחרו אם ה־Project פרטי או משותף, בהתאם למדיניות המשרד.
  5. אשרו את היצירה. לאחר שה־Project נפתח, הוסיפו Instructions וקבצים רק לאחר שהגדרתם מה שייך למרחב.
איך יודעים שההקמה הצליחה?
שם ה־Project מופיע ברשימת Projects, ונפתח מסך שבו אפשר להתחיל שיחה, להגדיר Instructions ולהוסיף Files. אל תבדקו את ההקשר לפי השם או התיאור בלבד, משום שהם אינם מקור ש־Claude קורא.
  1. בחרו שם קצר שאינו חושף פרטים רגישים שלא לצורך.
  2. הגדירו מטרה אחת: נוהל, תחום עבודה, לקוח, עסקה או תיק.
  3. בחרו הרשאות מצומצמות כאשר מדובר בחומר לקוח.
  4. אל תעלו קבצים לפני שהחלטתם מה שייך למרחב ומה לא.
3

להכיר את סביבת העבודה: שיחה, Instructions ו־Files

במסך ה־Project עובדים בשיחה בצד אחד, ומנהלים בצד האחר את ההוראות ואת בסיס הידע. ההפרדה חשובה: ההוראות קובעות כיצד לעבוד; הקבצים מספקים את החומר שעליו עובדים.

1
Instructions - כללי סגנון, בדיקה, מקורות, גבולות וסוג התוצר.
2
Files - המסמכים והתוכן הקבועים של הפרויקט.
3
Chat - המשימה הנוכחית והשאלות הממוקדות. קובץ שמצורף כאן נשאר קשור לשיחה זו, אלא אם הוספתם אותו גם ל־Files.
אילו הוראות חלות בתוך ה־Project

Personal Instructions ו־Project Instructions פועלות יחד

ההוראות האישיות ממשיכות להגדיר העדפות כלליות של החשבון. הוראות ה־Project מוסיפות את הכללים הייחודיים למרחב. כאשר כלל קריטי לעבודה משפטית, כתבו אותו במפורש ברמת ה־Project ובדקו שהתוצאה אכן מצייתת לו.

4

בחירת סוג ה־Project: שיטת עבודה, לקוח או עניין

בעבודה משפטית לא נכון להשתמש במרחב אחד לכל דבר. ההפרדה החשובה ביותר היא בין ידע קבוע של המשרד לבין חומר ששייך ללקוח או לעניין מסוים.

Project לשיטת עבודה

נוהל, תבניות, כללי סגנון, רשימות בדיקה ודוגמאות פיקטיביות או נטולות פרטים מזהים.

  • אין בו חומר של לקוחות אמיתיים.
  • מתאים ללמידה ולהכנת תהליך.
  • אפשר לעדכן בו תבנית אחת שמשמשת כמה משימות.

Project ללקוח או לעניין

מרחב נפרד שמכיל רק חומר של לקוח אחד, תיק אחד או עסקה אחת, ובהרשאות מצומצמות.

  • אין בו חומר של לקוחות אחרים.
  • השם אינו חייב לחשוף מידע רגיש.
  • הגישה ניתנת רק למי שצריך לעבוד בעניין.
מתי להקים Project נפרד

Project אחד אינו תיקייה לכל המשרד

כאשר מתחילים להוסיף חומר שאינו שייך למטרה שהוגדרה, עוצרים ומקימים מרחב נפרד.

5

למה להעלות ל־Project Files ולא רק לצ'אט?

שתי דרכי ההעלאה תקינות, אבל הן משרתות מטרות שונות. קובץ בצ'אט מתאים למשימה חד-פעמית. קובץ ב־Project Files מיועד להיות חלק מבסיס הידע הקבוע של המרחב ולעמוד לרשות שיחות נוספות באותו Project.

קובץ שמצורף לצ'אט

  • קשור לשיחה הנוכחית.
  • מתאים לניתוח חד-פעמי או לקובץ גדול.
  • מתאים במיוחד לתמונה או צילום מסך ש־Claude צריך לראות עכשיו.
  • אינו הופך אוטומטית לידע קבוע של ה־Project.

קובץ ב־Project Files

  • זמין כהקשר לשיחות בתוך אותו Project.
  • מתאים לנוהל, תבנית, חוזה, נספחים וחומר שחוזרים אליו.
  • ניתן להפנות אליו בשם מתוך Instructions.
  • דורש ניהול גרסאות והרשאות, משום שהוא משפיע על יותר משיחה אחת.
שאלהצירוף לצ'אטProject Files

איך בוחרים היכן לצרף קובץ

6

כתיבת Project Instructions שמגדירות כיצד להשתמש בקבצים

Instructions אינן צריכות לשכפל את המסמכים. הן מסבירות כיצד לעבוד במרחב: באילו קבצים להשתמש, איך לציין מקורות, כיצד לטפל בסתירה ומה אסור להסיק.

  1. פתחו את ה־Project הרצוי.
  2. לחצו על Set project instructions.
  3. הדביקו את כללי העבודה ולחצו על Save instructions.
  4. פתחו שיחה חדשה בתוך אותו Project ובדקו שההוראות משפיעות על התשובה בלי להעתיק אותן שוב לבקשה.

תבנית Instructions ל־Project משפטי

מטרת ה-Project: [תחום, לקוח או עניין].

מקורות עבודה:
1. לפני כל ניתוח, בדוק את הקבצים הרלוונטיים ב-Project Files.
2. ציין שם קובץ ומראה מקום לכל עובדה מרכזית.
3. הפרד בין עובדה במסמך, טענה של אדם, השערה ומידע חסר.
4. כאשר קיימת סתירה בין קבצים, הצג אותה ואל תפתור אותה ללא בסיס.

גבולות:
- אין להמציא עובדות, תאריכים, אסמכתאות או ציטוטים.
- אין לנסח מסקנה משפטית סופית ללא בקשה מפורשת ובדיקת עורך דין.
- אין להשתמש בחומר שאינו שייך ל-Project זה.

מבנה התשובה:
- מקורות שנבדקו
- עובדות
- טענות
- סתירות
- מידע חסר
- שאלות להמשך
הפניה מפורשת לקבצים

אפשר לציין במפורש את שמות הקבצים: "לפני הכנת מסמך ההכנה לפגישה, קרא את נוהל הפגישה ואת התבנית המאושרת". כך Claude יודע אילו קבצים לבדוק לפני ביצוע המשימה.

איך יודעים שה־Instructions פועלות?
פתחו שיחה חדשה בתוך ה־Project ובקשו משימה שמחייבת שימוש בכלל ששמרתם. התשובה צריכה ליישם את הכלל בלי שתעתיקו אותו שוב, ולציין את הקבצים שנבדקו כאשר ביקשתם זאת.
7

איך Claude קורא DOCX, PDF, תמונות וקובצי נתונים

לא כל קובץ מעובד באותה דרך. הבחירה בפורמט משפיעה על מה ש־Claude יכול לקרוא ועל מה שחייבים לבדוק ידנית.

סוג קובץמה Claude מקבלמתי מתאיםמה לבדוק
DOCXחילוץ טקסט. תמונות שמוטמעות במסמך אינן מפוענחות כחלק מהקובץ.טקסט של חוזה, נוהל, תכתובת או טיוטה.טבלאות, הערות שוליים, שינויים מסומנים, תמונות וחתימות.
PDFבקובצי PDF מתאימים Claude יכול לקרוא את הטקסט וגם לנתח רכיבים חזותיים. התיעוד הרשמי מתאר ניתוח חזותי לקובצי PDF שאורכם 100 עמודים או פחות. בקבצים בני 101 עד 1,000 עמודים העיבוד הוא טקסטואלי בלבד.מסמך שבו פריסה, טבלה, תרשים, חותמת או חתימה חשובים.מספור עמודי ה־PDF, איכות הסריקה והאם כל עמוד נקרא.
תמונה או צילום מסךניתוח חזותי כאשר התמונה מצורפת ישירות לשיחה.חתימה, צילום עמוד, מסך מערכת, תרשים או פרט גרפי.רזולוציה, חיתוך, טקסט קטן והקשר חסר.
CSV/XLSXנתונים טבלאיים. XLSX דורש שיכולת הרצת קוד ויצירת קבצים תהיה זמינה.טבלת חיובים, ציר זמן או רשימת מסמכים.נוסחאות, תאים מוסתרים, יחידות ופורמט תאריך.
מה אי אפשר להסיק מתצוגת DOCX: תצוגה עם כותרות וסימני # אינה הוכחה שה־DOCX הומר ונשמר כקובץ בפורמט .md. היא מוכיחה רק ש־Claude חילץ והציג ייצוג טקסטואלי לעבודה. התיעוד הרשמי אינו מתאר המרה קבועה ל־Markdown.
מתי לבחור PDF או תמונה?

כאשר הפריסה, החתימה, הטבלה או ההערה הגרפית הן חלק מהמידע שצריך לבדוק, אל תסתפקו ב־DOCX. צרפו PDF מתאים או את העמוד כתמונה לשיחה, ובקשו מ־Claude לתאר תחילה מה הוא רואה לפני ניתוח.

8

קיבולת, Search mode ו־RAG: מתי Claude מחפש בתוך הידע

כאשר בסיס הידע גדל, Claude יכול לעבור למצב חיפוש שמבוסס על RAG. במקום להכניס את כל התוכן לכל תשובה, הוא מחפש ומחזיר את הקטעים הרלוונטיים לשאלה. המעבר נעשה אוטומטית, ללא הגדרה ידנית.

Project capacityמדד שימוש בקיבולת המרחב. הוא אינו מספר עמודים ואינו מדד לאיכות.
Search modeמצביע על שימוש בחיפוש בידע כדי לאתר חומר רלוונטי.
עד פי 10המאמר הייעודי של Anthropic מציין ש־RAG עשוי להרחיב את קיבולת הידע עד פי 10.
סתירה בתיעוד הרשמי

המאמר הייעודי על RAG ממרץ 2026 אומר שהיכולת זמינה בכל התוכניות, בעוד עמוד Projects כללי עדיין מציג ניסוח שמגביל RAG לתוכניות בתשלום. לכן המדריך אינו מבטיח זמינות לפי מסלול. בודקים את הממשק בפועל ואת הופעת Search mode.

מה Search mode אינו מבטיח: הוא אינו מבטיח שכל מסמך שימש בכל תשובה. כשעובדה חשובה, בקשו שם קובץ, מראה מקום וציטוט קצר, ואז בדקו מול המקור.
9

הוספת ידע וניהול גרסאות

בממשק קיימות כמה דרכי הוספה: מהמחשב, טקסט ישיר, Google Drive ו־GitHub. האפשרויות בפועל משתנות לפי החשבון והחיבורים שהופעלו.

איך מוסיפים קובץ ל־Project Files?
פתחו את ה־Project. באזור Files או Project knowledge שמופיע במסך ה־Project, לחצו על כפתור ה־+. בחרו העלאה מהמחשב, הדבקת טקסט או מקור מחובר, לפי האפשרויות שמופיעות בחשבון. בסיום ודאו שהקובץ מופיע ברשימה בשם ובגרסה הנכונים.
Project לשיטת עבודהנוהל, תבנית, מדריך סגנון, רשימת בדיקות ודוגמה פיקטיבית.
Project לעניין מסויםהסכם, נספחים, תכתובת, ציר זמן וחומר ששייך לאותו עניין בלבד.
לא מעליםחומר שאינו נחוץ, קובץ של לקוח אחר או גרסה שאין דרך לזהות אם היא בתוקף.
  1. תנו לכל קובץ שם תיאורי: סוג מסמך, צדדים, תאריך וגרסה.
  2. העלו תחילה מספר קטן של מקורות מרכזיים.
  3. בדקו מה Claude חילץ מכל קובץ לפני משימה אמיתית.
  4. הסירו גרסה ישנה או סמנו אותה בבירור כלא בתוקף.
  5. אל תעלו חומר רגיש לפני שבדקתם מדיניות משרד, הרשאות והסכם השירות הרלוונטי.
10

בדיקה שהתשובה נשענת על הקבצים הנכונים

עצם הופעת הקבצים ברשימה אינה מוכיחה שהם נקראו או שהתשובה נשענת עליהם. מבצעים בדיקת הצלחה: מבקשים שמות קבצים ומראי מקום, ואז פותחים את המקורות ובודקים אותם בפועל.

בדיקת שימוש במקורות

לפני הכנת מסמך ההכנה לפגישה, בצע בדיקת מקורות:

1. רשום אילו קבצים קראת.
2. לכל עובדה מרכזית ציין שם קובץ ומראה מקום.
3. הפרד בין עובדה במסמך, טענה שנמסרה, השערה ומידע חסר.
4. הצג סתירות בין הקבצים.
5. אם חסר מקור, עצור ושאל לפני מסקנה.

לאחר מכן כתוב רק רשימת שאלות לפגישת הלקוח.
אל תנסח מסקנה משפטית.
איך קוראים את התוצאה?
  1. האם צוינו שמות הקבצים?
  2. האם לכל עובדה מרכזית יש מראה מקום?
  3. האם טענת לקוח נשארה טענה?
  4. האם סתירה הוצגה ולא נעלמה?
  5. האם Claude עצר כאשר חסר מקור?
מה עושים כשהתשובה אינה מציינת את הקובץ?

אל תמשיכו כאילו הכול תקין. ודאו שהקובץ קריא, הפנו אליו בשם, צמצמו את השאלה ובדקו שוב. חומר קריטי חייב להיות ניתן לאיתור ולאימות.

11

דוגמה משפטית מלאה: Project לעסקת מכר עם חמישה סוגי ידע

נניח שמקימים Project לעסקת מכר אחת. המטרה היא להכין מסמך הכנה לפגישה בלי לערב חומר מעסקה אחרת ובלי להפוך טענה לעובדה.

1. הסכםהטיוטה העדכנית.
2. נספחיםמפרט, תשריט ואישורים.
3. תכתובתשאלות והבהרות של הצדדים.
4. ציר זמןמועדים ופעולות.
5. תבניתמבנה מסמך ההכנה המאושר.

משימת פתיחה ל־Project של עניין

עבוד רק על בסיס הקבצים ב-Project זה.

הכן מסמך הכנה לפגישת הלקוח במבנה הבא:
1. מקורות שנבדקו.
2. עובדות שעולות במפורש מהמסמכים.
3. טענות שעולות מהתכתובת ואינן מאומתות.
4. סתירות בין ההסכם, הנספחים והתכתובת.
5. מועדים קריטיים ומקור כל מועד.
6. מידע חסר ושאלות שצריך להפנות ללקוח.

לכל סעיף ציין שם קובץ ומראה מקום.
אל תשלים מידע חסר ואל תנסח מסקנה משפטית סופית.
מדוע זה טוב יותר מצ'אט בודד?

אפשר לפתוח שיחה אחת לבדיקת מועדים, שיחה אחרת להשוואת גרסאות ושיחה נוספת להכנת פגישה - כולן נשענות על אותו בסיס ידע ואותן Instructions, בלי להעלות מחדש את החומר בכל פעם.

עבודה משותפת, הרשאות וגבולות

ב־Team וב־Enterprise אפשר לשתף Project בתוך הארגון. בהרשאת Can use המשתמש יכול לפתוח את ה־Project ולהשתמש בחומר בהתאם למדיניות הארגון. בהרשאת Can edit הוא יכול גם לשנות את ה־Project, את ההוראות ואת בסיס הידע. לכן הרשאת עריכה ניתנת רק למי שמוסמך לשנות חומר שמשפיע על כל הצוות.

ידע משותףאותם קבצים מאושרים.
כללים משותפיםאותן Instructions והבחנות.
בדיקה משותפתאותו תהליך אימות לפני שימוש.
כיצד משתפים Project?
פתחו את ה־Project ולחצו על Share project שמימין לשם ה־Project. הוסיפו חברים לפי שם או כתובת דוא"ל, הגדירו לכל אחד Can use או Can edit, ולחצו Share. לאחר מכן בקשו מאחד המשתמשים לפתוח את ה־Project ולוודא שהוא רואה רק את החומר שאליו התכוונתם לתת גישה. אם הכפתור אינו מופיע, בדקו שאתם בחשבון ארגוני ושיש לכם הרשאה לשתף את ה־Project.
נושאכלל עבודה
גישהנותנים גישה רק למי שצריך לעבוד בעניין.
עריכההרשאת עריכה ניתנת רק למי שמוסמך לשנות Instructions או ידע.
שם ה־Projectנמנעים מחשיפה מיותרת של פרטים רגישים בשם.
גרסאותשומרים מסמך עדכני ומסמנים או מסירים גרסה שאינה בתוקף.

סיכום: מתי משתמשים ב־Project ומתי ב־Skill

Project שומר הקשר

קבצים, הוראות וידע הקשורים ללקוח, לעניין או לשיטת עבודה מסוימת.

Skill מגדיר תהליך

רצף פעולות, שאלות, בדיקות ומבנה תוצר שחוזרים במשימות שונות.

  1. בחרו Project לשיטת עבודה, או Project נפרד ללקוח או לעניין אחד.
  2. הגדירו מטרה והרשאות לפני העלאת חומר.
  3. החליטו מה שייך ל־Project Files ומה מתאים לצ'אט חד-פעמי.
  4. כתבו Instructions קצרות שמגדירות מקורות, עובדות וגבולות.
  5. בחרו פורמט לפי הצורך: DOCX לטקסט, ו־PDF או תמונה כאשר הפריסה והרכיבים החזותיים חשובים.
  6. בדקו שימוש בקבצים באמצעות שם מקור ומראה מקום.
  7. הפרידו תהליך חוזר ל־Skill נפרד.
לפני שימוש ב־Project

הסיכון ב־Project שמערבב עניינים ומקורות
