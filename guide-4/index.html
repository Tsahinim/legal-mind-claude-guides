לפני חומר לקוח אמיתי

Project הוא שכבת ארגון - לא אישור להעלות כל מידע

בתרגול השתמשו בחומר ציבורי, פיקטיבי או נטול פרטים מזהים. לפני חומר אמיתי יש לבדוק את סוג החשבון, הרשאות הארגון, מדיניות המשרד, שמירת המידע והאנשים שמורשים לגשת למרחב.

1

מהו Project ולמה הוא שונה משיחה רגילה?

שיחה רגילה מתחילה מהבקשה ומהחומר שנמצא בה. Project הוא סביבת עבודה ייעודית: שיחות שנפתחות בתוכו מקבלות את ההוראות והקבצים ששייכים לאותו מרחב.

Chatהמשימה והשיחה שאתם מבצעים עכשיו.
Instructionsכיצד Claude צריך לעבוד בתוך המרחב.
Filesהמסמכים והידע שעליהם הוא רשאי להסתמך.
Personal Instructionsכללי החשבון האישיים ממשיכים לפעול ברקע.
במה זה עוזר לעורך דין?
  • לא להדביק מחדש את אותם נהלים ותבניות בכל שיחה.
  • לשמור את הידע הרלוונטי במקום קבוע ומוגדר.
  • לאפשר לאנשים שונים לעבוד לפי אותם סטנדרטים.
  • לצמצם ערבוב בין לקוחות, עניינים ומקורות.
הערה על Memory

אל תניחו ששיחה אחת בתוך Project זמינה אוטומטית לשיחה אחרת. מידע שחייב להישאר עקבי צריך להופיע ב־Files או ב־Instructions. Memory, כאשר הוא זמין, הוא שכבת עזר ולא תחליף לבסיס הידע של ה־Project.

2

ליצור Project חדש

השלב הראשון הוא לפתוח את אזור Projects וליצור מרחב עם שם ומטרה ברורים. השם צריך להסביר מה נמצא בפנים גם למי שלא היה בשיחה שבה הוא נוצר.

מה עושים עכשיו?

  1. פתחו את הסרגל הצדדי ובחרו Projects.
  2. לחצו על New project.
  3. כתבו שם שמתאר שיטה אחת, לקוח אחד או עניין אחד.
  4. תארו בקצרה מה אתם רוצים להשיג בתוך המרחב.
  5. לחצו Create project.

מה רואים בתמונה?

1
New project - מתחילים הקמה של סביבת עבודה ייעודית.
1
שם ה־Project - שם שמאפשר להבין מה נמצא במרחב.
2
המטרה - מה עושים כאן, לאילו משימות ולמי המרחב מיועד.
3
Create project - יוצרים את המרחב לאחר שההגדרה ברורה.
השם והתיאור מארגנים את המרחב - אך אינם הוראות ל־Claude
כדי שהמטרה תשפיע על כל השיחות, כתבו אותה גם ב־Project Instructions. אל תסתפקו בתיאור שמופיע בטופס ההקמה.
דוגמאות לשמות טובים

לקוח כהן - מחלוקת חוזית 2026

3

להכיר את סביבת העבודה שנפתחה

לאחר ההקמה נפתח מרחב עם אזור שיחה ובצדו שכבות ההקשר. שם מוסיפים את הכללים ואת החומר שעליהם Claude צריך להסתמך.

מה רואים בתמונה?

1
Instructions - הכללים שחלים על השיחות בתוך ה־Project.
2
Files - המסמכים והידע ש־Claude צריך לקרוא ולהפנות אליהם.

איך יודעים שהצלחתם? אתם יכולים להסביר במשפט אחד מה נשמר ב־Instructions ומה נשמר ב־Files, בלי לערבב ביניהם.

4

להחליט לפני ההעלאה: Project שיטה או Project של עניין?

בעבודה משפטית לא נכון להשתמש במרחב אחד לכל דבר. ההפרדה החשובה ביותר היא בין ידע קבוע של המשרד לבין חומר ששייך ללקוח או לעניין מסוים.

Project שיטה

מרכז נוהל, תבניות, כללי סגנון, רשימות בדיקה ודוגמאות פיקטיביות או נטולות פרטים מזהים.

  • אין בו חומר של לקוחות אמיתיים.
  • אפשר להשתמש בו ללמידה ולהכנת תהליך.
  • מתאים לידע של מחלקה או סוג משימה.

Project לקוח או עניין

מרחב נפרד שמכיל רק את החומר של לקוח אחד, תיק אחד או עסקה אחת, ובהרשאות מצומצמות.

  • אין בו חומר של לקוחות אחרים.
  • השם אינו חייב לחשוף מידע רגיש.
  • הגישה ניתנת רק למי שצריך לעבוד בעניין.
כלל פשוט

Project אחד אינו תיקייה לכל המשרד

כאשר אתם מתחילים להוסיף חומר שאינו שייך למטרה שהוגדרה, עצרו והקימו מרחב נפרד.

5

לכתוב הוראות שמחברות בין המשימה לבין הקבצים

הוראות Project אינן צריכות להכיל את כל הידע. הן מסבירות כיצד לעבוד במרחב: על אילו קבצים להסתמך, איך להציג אי־ודאות ומה אסור לעשות.

מה רואים בתמונה?

1
שדה ההוראות - כאן מגדירים מקורות, משמעת עובדתית, סגנון וגבולות.
2
Save instructions - שומרים רק לאחר שקראתם את ההוראות ובדקתם שאינן כוללות חומר לקוח.

הוראות קצרות להתחלה

מטרת סביבת העבודה: [Project שיטה / לקוח או עניין אחד].

הסתמך רק על הקבצים שהועלו לכאן ועל מידע שנמסר במפורש בשיחה.
כאשר אתה משתמש במקור, ציין שם קובץ, ובמידת האפשר גם עמוד, סעיף או פסקה.
הפרד בין עובדה המגובה במסמך, מידע שנמסר, טענה של צד, הנחה ומידע חסר.
אם קיימת סתירה בין מקורות, הצג אותה ואל תכריע ללא הנחיה.
אל תמציא עובדה, מועד, מסמך, ציטוט, דין, פסיקה או מקור.
אל תשלח, תשתף או תעדכן דבר ללא אישור מפורש.
פתיחת גרסה מלאה ל־Project שיטה

Project שיטה להכנת פגישות

ייעוד ה־Project
Project זה מרכז את הידע והכללים הקבועים להכנת פגישות במשרד.
הוא מיועד לנוהל, תבניות, מדריכי סגנון, רשימות בדיקה ודוגמאות פיקטיביות או נטולות פרטים מזהים.

איסור ערבוב
- אל תעבד כאן חומר של לקוח או תיק אמיתי.
- אל תערבב מידע בין לקוחות או עניינים.
- חומר אמיתי יעובד רק ב־Project נפרד שהוקם ללקוח או לעניין המסוים.

תפקיד Claude
פעל כעוזר משפטי־תפעולי שמארגן חומר ומיישם את שיטת המשרד.
אינך מחליף שיקול דעת משפטי ואינך מקור סמכות.

מקורות הידע
- הסתמך על הקבצים שהועלו ועל מידע שנמסר במפורש בשיחה.
- ציין שם קובץ, ובמידת האפשר גם עמוד, סעיף או פסקה.
- אם קיימת סתירה, הצג אותה ואל תכריע ללא הנחיה.
- אל תניח שמידע חשוב זמין אם אינו נמצא ב־Files או ב־Instructions.

משמעת עובדתית
הפרד בין:
- עובדה המגובה במסמך;
- מידע שנמסר על ידי לקוח;
- טענה של צד;
- הנחה או השערה;
- מידע חסר;
- נקודה המחייבת אימות אנושי.

גבולות
- כל פלט הוא חומר הכנה פנימי לבדיקת עורך דין.
- אל תמציא עובדה, מועד, מסמך, ציטוט, דין, פסיקה או מקור.
- אל תשלח, תשתף או תעדכן מערכת ללא אישור.
Project אינו Skill

בהוראות שומרים את ההקשר והכללים. רצף הפעולות המלא ומבנה תוצר שחוזרים בכל משימה יוגדרו ב־Skill נפרד.

6

להוסיף קבצים וידע שמתאימים למטרה

בתפריט Files אפשר להעלות קובץ מהמחשב, להוסיף תוכן טקסטואלי או לחבר מקור זמין. מתחילים קטן: שניים או שלושה קבצים שקל להבין ולבדוק.

מה רואים בתמונה?

1
אפשרויות הוספת ידע - קובץ מהמחשב, תוכן טקסטואלי או מקור מחובר כמו GitHub. האפשרויות בפועל עשויות להשתנות לפי החשבון.
Project שיטהנוהל, תבנית, מדריך סגנון, רשימת בדיקות ודוגמה פיקטיבית.
Project ענייןהסכם, תכתובת, מסמך שהתקבל, ציר זמן וחומר ששייך לאותו עניין בלבד.
לא מעליםקובץ שאינו נחוץ, חומר של לקוח אחר או גרסה שאינכם יודעים אם היא העדכנית.
נאמנות לרצף ההדגמה

העיקרון הוא להעלות שני קבצים שמגדירים את הסטנדרט, ואז לכתוב בהוראות ש־Claude חייב לקרוא אותם לפני יצירת התוצאה. בעולם המשפטי אלה יכולים להיות נוהל פגישה ותבנית מאושרת.

7

לבדוק שה־Project באמת משתמש בקבצים

עצם הופעת הקבצים ברשימה אינה מוכיחה שהם נקראו או שהמסקנה נשענת עליהם. שואלים שאלת בדיקה שמחייבת ציון מקורות ומראה מקום.

שאלת בדיקה לאחר העלאת הקבצים

לפני כתיבת בריף, בצע בדיקת מקורות:

1. רשום אילו קבצים קראת.
2. לכל עובדה מרכזית ציין שם קובץ ומראה מקום.
3. הפרד בין עובדה במסמך, טענה שנמסרה, הנחה ומידע חסר.
4. הצג סתירות בין הקבצים.
5. אם חסר מקור, עצור ושאל לפני מסקנה.

לאחר מכן כתוב רק רשימת שאלות לפגישת הלקוח.
אל תנסח מסקנה משפטית.
איך קוראים את התוצאה?
  1. האם Claude ציין את שמות הקבצים שקרא?
  2. האם לכל עובדה מרכזית יש מראה מקום?
  3. האם טענה של לקוח נשארה טענה ולא הפכה לעובדה?
  4. האם סתירה הוצגה במקום להיעלם?
  5. האם Claude עצר כאשר חסר מקור?
לא הסתמך על הקובץ?

אל תמשיכו כאילו הכול תקין. חדדו את ההוראות, ודאו שהקובץ קריא ושאלו שוב. מידע קריטי צריך להיות ניתן לאיתור ולאימות.

8

עבודה משותפת: אותו הקשר, אותן הוראות, אותן מגבלות

היתרון לצוות אינו רק שכולם רואים את אותם קבצים. הם גם עובדים לפי אותן הוראות ובאותו גבול מקצועי, במקום שכל אחד יבנה מחדש את ההקשר בשיחה פרטית.

ידע משותףאותם קבצים מאושרים.
כללים משותפיםאותן הוראות והבחנות.
בדיקה משותפתאותו תהליך אימות לפני שימוש.
שיתוף Projects תלוי בסוג החשבון
בחשבונות Team או Enterprise ניתן לשתף Project עם חברי הארגון ולהבחין בין הרשאת שימוש לבין הרשאת עריכה. בחשבון אישי ייתכן שלא תופיע אפשרות שיתוף ארגונית.
נושאכלל עבודה
גישהנותנים גישה רק למי שצריך לעבוד בעניין.
שם המרחבנמנעים מחשיפה מיותרת של פרטים רגישים בשם.
גרסאותשומרים מסמך עדכני ומסמנים גרסאות שאינן בתוקף.
סיום ענייןבודקים הרשאות, ייצוא, שמירה ומחיקה לפי מדיניות המשרד.
פעולה חיצוניתשליחה, שיתוף או עדכון מערכת דורשים אישור מפורש.
9

Project מול Skill: הקשר לעומת תהליך

המעבר הבא בסדרה הוא Skills. ההבחנה פשוטה: Project מספק את הידע וההקשר; Skill מלמד את Claude כיצד לבצע משימה חוזרת.

Project = Context

קבצים, הוראות, ידע קבוע, לקוח או עניין מסוים.

Skill = Process

רצף פעולות, שאלות, בדיקות ומבנה תוצר שחוזרים במשימות שונות.

דוגמה
Project שיטה מכיל נוהל פגישה, תבנית ומדריך סגנון.
Skill להכנת בריף שואל שאלות, ממיין עובדות וחוסרים ומפיק מסמך במבנה קבוע.
המעבר למדריך הבא

במדריך 5 נראה כיצד Skills, Connectors ו־Projects מתחברים למערכת עבודה אחת. ההדרכה המלאה לבניית Skills נשארת במרכז ה־Skills הנפרד.

10

סיכום: להקים Project ראשון בלי להעמיס

  1. בחרו Project שיטה או Project של לקוח/עניין אחד.
  2. תנו שם ומטרה שמגדירים את גבולות המרחב.
  3. כתבו הוראות קצרות שמגדירות מקורות, עובדות וגבולות.
  4. העלו שני קבצים בלבד ובדקו שימוש בהם.
  5. דרשו שם קובץ ומראה מקום לכל עובדה מרכזית.
  6. הפרידו את התהליך החוזר ל־Skill נפרד.
כלל העבודה המשפטית

Project טוב מצמצם ניחושים - Project מעורבב מגדיל סיכון

המטרה אינה להעלות כמה שיותר חומר. המטרה היא ליצור מרחב שמאפשר להבין מה שייך אליו, על אילו מקורות הוא נשען ומי רשאי לעבוד בו.

איך יודעים שהצלחתם? Claude מציין את המקור שבו השתמש, מציג מידע חסר או סתירה ואינו מערב ידע ממרחב אחר.
