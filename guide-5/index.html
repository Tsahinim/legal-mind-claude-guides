Skills: מתי מתאים להגדיר תהליך חוזר

לומדים מהו Skill, מה ההבדל בינו לבין Project, אילו תהליכים מתאימים לו ואילו בדיקות נדרשות לפני שהופכים דרך עבודה לתהליך חוזר.

על המדריך

מה תדעו בסוף?להסביר מהו Skill, להבדיל בינו לבין Project, לזהות מועמד מתאים ולהבין את שלבי הבנייה בקצרה.
למי המדריך מתאים?למי שכבר מכיר שיחות, הוראות קבועות ו־Projects ורוצה להבין כיצד Claude יכול לבצע תהליך חוזר לפי הוראות קבועות.
מה לא עושים כאן?לא בונים, מתקינים או אורזים Skill בפועל. הפעולות האלה נלמדות בסדרה המדריך המקיף ל־Skills לעורכי דין.
היקף המדריך

מה נלמד כאן ומה נשאר למדריך ההמשך

המדריך שלפניכם מסביר מהו Skill ומתי הוא מתאים, וזה כל תפקידו. יצירת הקבצים, ההתקנה, הבדיקות והתחזוקה נלמדות בסדרה נפרדת ומפורטת בהרבה, ששמה המדריך המקיף ל־Skills לעורכי דין והיא בת חמישה מדריכים. אם אתם מחפשים כאן הוראות בנייה בפועל, לא תמצאו אותן, והן אינן חסרות בטעות.

בדיקה לפני בנייה

לפני שבונים Skill, בודקים שהתהליך עצמו נכון

Skill אינו הופך ניסוח לנכון או מסקנה למאושרת. לפני שמפעילים תהליך חוזר על חומר אמיתי, מגדירים בדיקות, עובדים עם דוגמאות פיקטיביות ומוודאים שמידע חסר מוביל לשאלה או לסימון חוסר ולא להמצאה.

1

מהו Skill ומה ההבדל בינו לבין Project?

Skill הוא תיקייה של הוראות, דוגמאות ומשאבים שמלמדת את Claude לבצע משימה מסוימת באופן עקבי במשימות חוזרות. כאשר ה־Skill פעיל ורלוונטי לבקשה, Claude טוען את ההוראות הדרושות ומיישם אותן, במקום שתדביקו את כל התהליך מחדש בכל שיחה.

איך מגיעים ל־Skills ומפעילים Skill?
בחשבון אישי ודאו ש־Code execution and file creation פעיל ב־Settings > Capabilities. לאחר מכן פתחו Customize > Skills והפעילו את ה־Skill הרצוי באמצעות המתג שלצדו. בחשבון Team או Enterprise ייתכן שמנהל הארגון צריך לאפשר את היכולת. אם Skills אינו מופיע לאחר ההפעלה, בדקו שאתם נמצאים בחשבון ובארגון הנכונים ופנו למנהל הארגון. לאחר ההפעלה Claude משתמש ב־Skill באופן אוטומטי כאשר הבקשה מתאימה לתיאור שלו.
תנאי זמינות חשוב
Skills זמינים בתוכניות Claude השונות, אך דורשים הפעלה של Code execution. בחשבונות Team או Enterprise ייתכן שמנהל הארגון צריך לאפשר את היכולת לפני שהיא תופיע למשתמשים.

Project מרכז מסמכים והוראות של עניין

מסמכים, עובדות, הנחיות וידע של לקוח, עניין או מחלקה מסוימת.

Skill מגדיר שלבים ותוצר שחוזרים בין משימות

שלבי העבודה, שאלות החובה, הבדיקות ומבנה התוצר שחוזרים בין מקרים.

דוגמה משפטית

Project של תיק מסוים יכול להחזיק הסכם, התכתבויות ועובדות. Skill להכנת מסמך הכנה לפגישת לקוח יכול להגדיר בכל תיק אילו שאלות לשאול, כיצד להפריד בין עובדות לטענות ואיך להציג מסמכים חסרים.

Skill אינו זיכרון של תיק, אינו מאגר מסמכים ואינו תחליף לשיקול דעת משפטי.

2

מתי תהליך מתאים להפוך ל־Skill?

לא כל בקשה חוזרת מצדיקה Skill. תהליך מתאים במיוחד ל־Skill כאשר המבנה שלו יציב, גם אם העובדות והלקוח משתנים בכל פעם.

  • המשימה חוזרת שוב ושוב ודורשת בכל פעם אותן הוראות בסיס.
  • אפשר להגדיר בבירור איזה מידע נכנס ואיזה תוצר צריך לצאת.
  • קיימים כללי איכות שאפשר לבדוק, למשל מבנה, שדות חובה והפרדה בין עובדה להשערה.
  • הידע משתנה בין מקרים, אך דרך העבודה נשארת דומה.
  • ריכוז ההוראות במקום אחד צריך למנוע עדכון ידני של אותו פרומפט בכל שיחה.
מתי לא להשתמש ב־Skill

משימה חד-פעמית, סוגיה שעדיין אין לה שיטת עבודה יציבה, או עבודה שתלויה כמעט כולה בשיקול דעת מקצועי משתנה מתאימות פחות לבניית Skill ראשון.

3

שלבי בניית Skill - מבט כללי לפני הסדרה המעשית

הבנייה כוללת אפיון, יצירה, בדיקה, התקנה ושיפור. כאן מוצגים השלבים כדי שתבינו את הרצף; ההוראות המעשיות והקבצים מופיעים בסדרה המדריך המקיף ל־Skills לעורכי דין.

1. מזהים
משימה חוזרת וממוקדת
2. מאפיינים
קלט, תוצר וכללי איכות
3. בונים
הוראות ודוגמאות
4. בודקים
תוצר דוגמה ומקרים חריגים (מקרי קצה)
5. מתקינים ומשפרים
על מקרה חדש

כדי לנהל Skills קיימים, פתחו Customize > Skills. במסך זה אפשר להפעיל או להשבית Skill באמצעות המתג שלצדו. כדי להעלות Skill מותאם אישית פותחים Customize > Skills > + > + Create skill > Upload a skill ובוחרים קובץ ZIP שמכיל את תיקיית ה־Skill. במדריך הנוכחי איננו מבצעים את ההעלאה, משום שתחילה צריך לבנות ולבדוק את התיקייה ואת קובץ skill.md.

מה אמור להופיע לאחר העלאה תקינה?
ה־Skill מופיע ברשימת ה־Skills וניתן להפעיל או להשבית אותו. לאחר ההפעלה Claude משתמש בו כאשר הבקשה מתאימה לתיאור שלו. כדי לבדוק זאת, מריצים משימת דוגמה שמחייבת את שלבי ה־Skill ומשווים את התוצאה למבנה ולכללי האיכות שהוגדרו. בדיקות ההפעלה המלאות נלמדות בסדרה המדריך המקיף ל־Skills לעורכי דין.
מה כולל המסלול? זיהוי המשימה, יצירה עם Claude, שאלות אפיון, הגדרת קלט ותוצר, תנאי הפעלה, תוצר בדיקה, העתקה לחשבון, הרצה על מקרה חדש ושיפור התהליך. כאן הם מוצגים כמפה; בסדרה המדריך המקיף ל־Skills לעורכי דין הם הופכים להדרכה מעשית מלאה.
4

מה נלמד בסדרה המדריך המקיף ל־Skills לעורכי דין

הסדרה המדריך המקיף ל־Skills לעורכי דין כוללת את שלבי הבנייה המעשיים שאינם מבוצעים במדריך הנוכחי:

  • בחירת תהליך משפטי מתאים והגדרת גבולותיו.
  • בנייה עם Claude וגם הבנת מבנה skill.md - קובץ ההוראות המרכזי של ה־Skill.
  • ניסוח תיאור ותנאי הפעלה שאינם רחבים מדי.
  • בניית דוגמאות, מקרי בדיקה ו־Golden Cases - דוגמאות בדיקה עם תוצאה צפויה.
  • בדיקת קבצים, התקנה, הפעלה והשוואה בין גרסאות.
  • אבטחת מידע, חיסיון, הרשאות ומקורות מהימנים.
  • אריזה, הפצה, תחזוקה ושיפור על בסיס תוצאות הבדיקות והשימוש בפועל.
היכן ממשיכים בפועל

הבנייה המעשית, ההתקנה, הבדיקות, האבטחה והתחזוקה נלמדות בסדרה נפרדת ומעמיקה בהרבה, בשם המדריך המקיף ל־Skills לעורכי דין. זו סדרה בת חמישה מדריכים, בהיקף של כשלוש שעות למי שמבצע בפועל, והיא מלמדת אפיון תהליך, בניית הקבצים, התקנה, בדיקות איכות, הרשאות ותחזוקת גרסאות.

המדריך שלפניכם אינו מקצר את הסדרה ההיא ואינו מחליף אותה. הוא עונה על שאלה אחת בלבד: האם התהליך שלכם מתאים ל־Skill. אם התשובה חיובית, בקשו מהמשרד את הגישה לסדרה המדריך המקיף ל־Skills לעורכי דין.

5

סיכום: כיצד לזהות תהליך שמתאים ל־Skill

כעת אתם יודעים ש־Project מרכז את החומר וההוראות של עניין, Skill מגדיר תהליך שחוזר בין משימות, הרכיב השלישי, Connector, שמחבר את Claude לשירות חיצוני כמו יומן או דואר, נלמד במדריך הבא. בשלב הזה בחרו תהליך אחד ובדקו אם הוא ממוקד, חוזר ואם אפשר לבדוק באופן ברור את התוצאה שלו.

ארבע שאלות לפני שמחליטים לבנות Skill

  • מהי המשימה שחוזרת?
  • איזה מידע משתנה בכל מקרה?
  • אילו שלבים וכללי איכות חייבים להישאר קבועים?
  • איזו טעות אסור לתהליך לשכפל?
תרגיל קצר

בחרו משימה פיקטיבית אחת, למשל הכנת מסמך הכנה לפגישת לקוח, וענו על ארבע השאלות. אל תבנו עדיין את ה־Skill. המטרה בשלב הזה היא לבדוק שהמשימה ממוקדת וניתנת לבדיקה.

במדריך הבא נלמד כיצד לחבר שירות חיצוני באמצעות Connector, להגדיר הרשאות ולבדוק את מקור המידע שנשלף.
